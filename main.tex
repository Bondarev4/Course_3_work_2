\section*{Введение}

    Современное сельское хозяйство переживает период цифровой трансформации, которая затрагивает все аспекты агропромышленного комплекса — от управления фермерскими хозяйствами до прогнозирования урожайности и диагностики болезней растений. Внедрение информационных технологий в аграрный сектор позволяет существенно повысить эффективность производства, снизить потери урожая и оптимизировать использование ресурсов.

    Особую актуальность в последние годы приобретают системы поддержки принятия решений на основе искусственного интеллекта. Такие системы способны анализировать большие объёмы данных, выявлять скрытые закономерности и предоставлять рекомендации, сравнимые по качеству с советами опытных агрономов. Это особенно важно для малых и средних фермерских хозяйств, которые не всегда могут позволить себе нанять квалифицированного агронома.

    Однако распространение зарубежных решений в России столкнулось с серьёзными препятствиями. Начиная с 2022 года, многие международные IT-компании прекратили свою деятельность на территории РФ, а доступ к ключевым сервисам разработки (PyPI, GitHub, Hugging Face) был ограничен. Это создало необходимость поиска альтернативных путей разработки и использования технологий искусственного интеллекта в российском аграрном секторе.

    В связи с этим разработка отечественного веб-приложения «Цифровой агроном», которое объединяет возможности машинного обучения для прогнозирования урожайности и консультационного ИИ-ассистента, является своевременной и востребованной задачей. Такое приложение может стать доступным инструментом для фермеров, агрономов и садоводов, предоставляя им квалифицированную помощь в режиме 24/7.

    Целью данной работы является проектирование, разработка и экспериментальная апробация веб-приложения «Цифровой агроном» с ИИ-ассистентом, обеспечивающего прогнозирование урожайности на основе ML-модели и консультационную поддержку.

    Для достижения цели требуется решить следующие задачи:
    \begin{enumerate}
        \item Провести анализ существующих систем поддержки принятия решений в сельском хозяйстве, выявить их достоинства и недостатки.
        \item Изучить проблемы импортозамещения и доступности технологий искусственного интеллекта на территории Российской Федерации.
        \item Обосновать выбор оптимального стека технологий с учётом выявленных ограничений.
        \item Спроектировать модульную архитектуру веб-приложения, определить взаимодействие между компонентами.
        \item Реализовать программный прототип, включающий ML-модель прогнозирования урожайности и ИИ-ассистента.
        \item Провести тестирование разработанной системы и оценить качество её работы по различным метрикам.
    \end{enumerate}

    Объектом исследования являются процессы поддержки принятия решений в растениеводстве, включая прогнозирование урожайности, выбор культур для посева и консультационную поддержку.

    Предметом исследования выступают методы машинного обучения (в частности, Random Forest) для прогнозирования урожайности, а также технологии построения ИИ-ассистентов на основе больших языковых моделей и API-сервисов.

    Практическая значимость работы состоит в возможности использования разработанного веб-приложения фермерскими хозяйствами, агрономическими службами и садоводами для поддержки принятия решений по выбору культур, планированию севооборота и получению консультаций по уходу за растениями.

    Методология исследования включает анализ научной и технической литературы, изучение документации библиотек машинного обучения, проектирование архитектуры приложения, реализацию программного прототипа на языке Python с использованием фреймворка Flask и библиотеки scikit-learn, а также экспериментальную оценку качества работы системы.

\section{Глава 1. Теоретическая часть}

\subsection{Эволюция систем поддержки принятия решений в сельском хозяйстве}

    Системы поддержки принятия решений (СППР) в сельском хозяйстве прошли долгий путь эволюции — от простых бумажных справочников до сложных интеллектуальных систем на основе искусственного интеллекта \cite{evolution}. Понимание этой эволюции важно для оценки текущего уровня развития технологий и определения направлений их совершенствования.

    На начальном этапе (1960–1980-е годы) основным инструментом агронома были бумажные карты полей, справочники по сортам культур, удобрениям и средствам защиты растений. Агрономы полагались исключительно на личный опыт и интуицию, что приводило к высокому риску ошибок и невозможности масштабирования знаний. Каждое хозяйство накапливало собственный опыт, который часто не передавался другим.

    С появлением персональных компьютеров в 1980-х годах начали разрабатываться первые электронные базы данных по сортам культур, удобрениям и средствам защиты растений. Это позволило ускорить доступ к информации, систематизировать справочные данные и упростить их поиск. Однако такие системы были пассивными — они предоставляли информацию, но не анализировали её и не генерировали рекомендации.

    В 1990-е годы с развитием спутниковых технологий и глобальных систем позиционирования (GPS) возникло понятие «точного земледелия» (precision agriculture) \cite{precision}. Появились системы мониторинга полей, позволяющие учитывать пространственную неоднородность почв и рассчитывать вегетационный индекс растений (NDVI) на основе спутниковых снимков. Эти системы собирали большие объёмы пространственных данных, но их анализ всё ещё требовал участия человека. Именно в этот период начали формироваться предпосылки для использования методов машинного обучения в сельском хозяйстве.

    Современный этап (2010-е годы – настоящее время) характеризуется массовым внедрением технологий искусственного интеллекта, машинного обучения и компьютерного зрения. Этот переход стал возможным благодаря трём ключевым факторам: росту вычислительных мощностей (особенно графических процессоров GPU), доступности больших размеченных датасетов (например, PlantVillage содержит более 54 тысяч изображений здоровых и больных растений) и развитию библиотек глубокого обучения (TensorFlow, PyTorch, Keras).

    В настоящее время существует несколько категорий систем поддержки принятия решений в сельском хозяйстве:

    \begin{itemize}
        \item Диагностика болезней по фото (Plantix) — мобильное приложение, использующее свёрточные нейронные сети для определения болезней растений по фотографии. Охватывает более 30 культур и 400 болезней. Пользователю достаточно сфотографировать лист растения, и приложение в течение нескольких секунд выдаёт диагноз и рекомендации по лечению.
        
        \item Мониторинг полей (Climate FieldView) — комплексная платформа, объединяющая спутниковые снимки, данные с наземных датчиков, историю полей и погодные сервисы. Система позволяет оптимизировать сроки посева, полива и внесения удобрений.
        
        \item Экспертные системы (Agrobase) — базы знаний по средствам защиты растений с модулем принятия решений. Агроном может указать культуру, стадию вегетации и наблюдаемые симптомы, а система предложит список рекомендуемых препаратов.
        
        \item ERP-системы для АПК — комплексные системы управления сельскохозяйственным предприятием, включающие модули планирования посевных площадей, учёта материальных ресурсов, анализа эффективности производства.
        
        \item ИИ-ассистенты — чат-боты на основе больших языковых моделей, отвечающие на вопросы фермеров в диалоговом режиме. Такие системы могут давать советы по уходу за культурами, диагностировать болезни по описанию симптомов и интерпретировать результаты прогнозов.
    \end{itemize}

    Анализ существующих решений позволяет сделать следующие выводы. Во-первых, большинство зарубежных продуктов (Plantix, Climate FieldView) после 2022 года стали недоступны для российских пользователей или требуют оплаты в валюте, что затрудняет их использование. Во-вторых, существующие экспертные системы часто содержат устаревшую информацию, так как обновление баз знаний требует постоянных усилий разработчиков. В-третьих, универсальные ИИ-ассистенты (ChatGPT, GigaChat, YandexGPT) не обладают специализированными знаниями в области агрономии и могут давать общие или неточные ответы на профессиональные вопросы.

    Таким образом, актуальность разработки отечественной системы поддержки принятия решений в растениеводстве не вызывает сомнений. Такая система должна объединять возможности машинного обучения для прогнозирования, экспертные знания по севообороту и современные технологии диалоговых ИИ-ассистентов.

\subsection{Методы искусственного интеллекта и машинного обучения в растениеводстве}

    Современные методы искусственного интеллекта открывают новые возможности для автоматизации диагностики, прогнозирования и консультирования в сельском хозяйстве. Рассмотрим основные группы методов.

    \textbf{Прогнозирование урожайности.} Это задача регрессии — предсказания непрерывного значения на основе набора признаков: климатических (температура, осадки, влажность, солнечная радиация), почвенных (тип почвы, pH, содержание гумуса), агротехнических (культура, сорт, удобрения, пестициды) и временных (год, сезон, фаза вегетации).

    Алгоритм Random Forest (случайный лес) \cite{randomforest} является одним из наиболее эффективных методов для прогнозирования урожайности. Он представляет собой ансамбль (совокупность) множества деревьев решений, каждое из которых обучается на случайной подвыборке данных. Итоговый прогноз получается усреднением предсказаний всех деревьев. Ключевые преимущества Random Forest для данной задачи: устойчивость к переобучению благодаря усреднению большого количества деревьев; способность работать с разнородными признаками (категориальными и числовыми) без предварительного масштабирования; автоматическое определение важности признаков — можно понять, какие факторы наиболее сильно влияют на урожайность; устойчивость к выбросам и пропускам в данных.

    Другим популярным методом является Gradient Boosting (градиентный бустинг), реализованный в библиотеках XGBoost, LightGBM и CatBoost. В отличие от Random Forest, где деревья строятся независимо, в градиентном бустинге каждое следующее дерево обучается на ошибках предыдущего. Это позволяет достичь более высокой точности, но требует больше вычислительных ресурсов и более тщательной настройки гиперпараметров.

    Для учёта временных зависимостей в данных (например, последовательности урожайности по годам) применяются рекуррентные нейронные сети, в частности архитектура LSTM (Long Short-Term Memory) \cite{lstm}. LSTM способна «запоминать» долгосрочные зависимости, что важно для прогнозирования по временным рядам. Однако нейросетевые методы требуют значительно большего объёма данных и вычислительных ресурсов по сравнению с Random Forest.

    \textbf{Компьютерное зрение.} Диагностика болезней по фотографиям листьев является задачей классификации изображений. Традиционные методы основаны на выделении признаков вручную (цветовые гистограммы, текстурные дескрипторы) с последующей классификацией (SVM, Random Forest). Методы глубокого обучения используют свёрточные нейронные сети (CNN), которые автоматически извлекают признаки. Наиболее популярные архитектуры: ResNet50 (точность 99,2\%), InceptionV3 (98,5\%), YOLOv8 (97,7\%) \cite{yolo}. Основное преимущество CNN — инвариантность к масштабу, повороту и сдвигу изображения.

    \textbf{Большие языковые модели (LLM).} LLM — нейросетевые архитектуры на основе трансформеров с механизмом внимания (attention) \cite{attention}, обученные на огромных объёмах текстовых данных (триллионы токенов). Ключевая инновация — механизм внимания, позволяющий модели фокусироваться на наиболее релевантных частях входного текста при генерации ответа.

    Применение LLM в сельском хозяйстве: консультации по уходу за культурами в естественном диалоговом режиме; диагностика болезней по текстовому описанию симптомов; рекомендации по лечению и профилактике; интерпретация ML-прогнозов для конечного пользователя.

    Архитектура RAG (Retrieval-Augmented Generation) дополняет LLM поиском по внешней базе знаний, что позволяет использовать актуальные агрономические справочники и снижает риск «галлюцинаций» модели.

\subsection{Проблемы импортозамещения в области IT для сельского хозяйства}

    Начиная с 2022 года, российские разработчики столкнулись с серьёзными ограничениями доступа к зарубежной IT-инфраструктуре \cite{blocks}. Рассмотрим основные проблемы и найденные решения.

    \textbf{Блокировка ресурсов.} В 2022–2024 годах в России был ограничен доступ к ряду ключевых сервисов:
    
    \begin{itemize}
        \item PyPI.org — основной репозиторий пакетов Python. Блокировка домена .org сделала невозможной автоматическую установку библиотек через \texttt{pip install}. Решение: использование отечественных зеркал (pypi.org.ru) или ручная установка из скачанных \texttt{.whl}-файлов.
        \item GitHub — крупнейший хостинг кода. Ограничения затронули доступ к репозиториям и Actions. Решение: использование зеркал или GitLab на собственной инфраструктуре.
        \item Hugging Face — платформа для дистрибуции ML-моделей. Ограничения затруднили скачивание предобученных весов. Решение: локальное хранение моделей и использование альтернативных источников.
    \end{itemize}

    \textbf{Проблемы совместимости библиотек.} Выход NumPy 2.0 в 2024 году создал серьёзную проблему — многие библиотеки (OpenCV, Ultralytics YOLO, некоторые модули scikit-learn) были собраны с использованием NumPy 1.x API и перестали работать с новой версией \cite{numpy}. Решение: фиксация совместимых версий в \texttt{requirements.txt} (\texttt{numpy==1.24.3}, \texttt{scikit-learn==1.3.2}) и отказ от обновления до полной стабилизации экосистемы.

    \textbf{Альтернативы для LLM.} Локальный запуск LLM требует мощного GPU с большим объёмом видеопамяти (от 16 ГБ для моделей 7B параметров), что недоступно в рамках курсовой работы. Облачные сервисы российских провайдеров (YandexGPT, GigaChat) имеют ограничения на бесплатные запросы и не всегда предоставляют нужный уровень качества. Решение: использование OpenRouter API \cite{openrouter}, который агрегирует множество моделей, принимает оплату в криптовалюте и стабильно работает на территории РФ. В качестве HTTP-клиента используется встроенная библиотека \texttt{urllib}, что позволило отказаться от внешней зависимости \texttt{requests}.

    Таким образом, успешная разработка IT-решений в текущих условиях требует от разработчика не только знания технологий, но и умения адаптироваться к ограничениям, искать обходные пути и проверять совместимость версий. Опыт, полученный в ходе данной работы, может быть полезен при разработке других проектов в области агротехнологий.

\subsection{Критерии оценки качества системы}

    Для объективной оценки разработанной системы необходимо определить набор количественных метрик, по которым будет оцениваться качество работы. Метрики разделены на три категории: метрики ML-модели, технические метрики и бизнес-метрики.

    \textbf{Метрики ML-модели прогнозирования урожайности:}

    \begin{itemize}
        \item \textbf{R² (коэффициент детерминации)} — показывает, какую долю дисперсии целевой переменной объясняет модель. Вычисляется по формуле: 
        \[
        R^2 = 1 - \frac{\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}{\sum_{i=1}^{n}(y_i - \bar{y})^2}
        \]
        Значение 1 соответствует идеальному предсказанию (модель объясняет 100\% дисперсии). Значение 0 означает, что модель предсказывает не лучше, чем простое среднее.

        \item \textbf{RMSE (Root Mean Square Error)} — среднеквадратичная ошибка. Вычисляется по формуле:
        \[
        \text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}
        \]
        Измеряется в тех же единицах, что и целевая переменная (ц/га). Более чувствительна к большим ошибкам, чем MAE.

        \item \textbf{MAE (Mean Absolute Error)} — средняя абсолютная ошибка. Вычисляется по формуле:
        \[
        \text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|
        \]
        Менее чувствительна к выбросам, чем RMSE. Легко интерпретируется.

        \item \textbf{Относительная точность} — вычисляется как $1 - \text{MAE}/\bar{y}$. Показывает среднюю процентную точность прогноза.
    \end{itemize}

    \textbf{Технические метрики:}

    \begin{itemize}
        \item \textbf{Время инференса ML-модели} — время от получения входных параметров до выдачи прогноза. Измеряется в миллисекундах. Целевое значение — менее 100 мс для комфортной работы пользователя.
        \item \textbf{Время ответа API чата} — время от отправки запроса к OpenRouter API до получения ответа. Измеряется в секундах. Целевое значение — менее 5 секунд с учётом сетевых задержек.
        \item \textbf{Время загрузки страницы} — время полной загрузки HTML-страницы с CSS и JS. Измеряется инструментами разработчика браузера. Целевое значение — менее 2 секунд.
    \end{itemize}

    \textbf{Бизнес-метрики:}

    \begin{itemize}
        \item \textbf{Процент автоответов чата} — доля пользовательских запросов, которые могут быть обработаны fallback-режимом без обращения к API. Измеряется в процентах. Целевое значение — более 65\%.
        \item \textbf{Уверенность прогноза} — вычисляется на основе того, насколько год прогноза близок к обучающей выборке (1990–2013). Целевое значение — более 70\% для годов до 2013.
        \item \textbf{Покрытие культур} — количество различных культур, для которых система может сделать прогноз. Целевое значение — более 5 культур.
    \end{itemize}

    Оценка системы по этим метрикам будет проведена во второй главе после реализации программного прототипа.

\subsection{Архитектура веб-приложения}

    Разработанное веб-приложение «Цифровой агроном» построено по классической клиент-серверной архитектуре, которая является стандартом для веб-приложений. Такая архитектура обеспечивает разделение ответственности: клиентская часть отвечает за отображение интерфейса и взаимодействие с пользователем, а серверная — за бизнес-логику, машинное обучение и хранение данных.

    Выбор клиент-серверной архитектуры обусловлен следующими преимуществами: централизованное хранение данных и моделей машинного обучения — не нужно устанавливать модели на каждое устройство пользователя; независимость клиентской части от платформы — пользователь может работать с приложением через любой современный браузер; упрощение обновлений — достаточно обновить серверную часть, клиенты получат изменения автоматически; масштабируемость — при росте нагрузки можно добавить дополнительные серверы.

    Система состоит из следующих модулей: модуль веб-интерфейса (Frontend) — реализован на HTML, CSS и JavaScript, отвечает за отображение страниц, ввод данных пользователем и отображение результатов, взаимодействует с сервером через асинхронные AJAX-запросы (fetch API); серверный модуль (Backend) — реализован на Flask, принимает HTTP-запросы от клиента, маршрутизирует их к соответствующим обработчикам, вызывает функции ML-модулей и возвращает ответы в формате JSON; модуль прогнозирования урожайности (yield\_predictor.py) — содержит ML-модель Random Forest Regressor, обученную на данных FAO, предсказывает урожайность культуры в заданном регионе при заданных климатических условиях; модуль сравнения культур (crop\_comparator.py) — содержит ML-модель Random Forest Classifier, для заданных климатических условий определяет рейтинг культур по пригодности; модуль севооборота (rotation\_predictor.py) — основан на агрономических правилах, рекомендует, какие культуры следует посадить после заданной; модуль ИИ-ассистента (ai\_assistant.py) — взаимодействует с OpenRouter API для получения ответов от LLM, содержит fallback-режим на случай недоступности API; модуль агрономической аналитики (ml\_analytics.py) — унифицированный интерфейс для доступа ко всем ML-модулям, упрощает вызов функций из серверного модуля; модуль конфигурации (config.py) — загружает переменные окружения из файла .env (API-ключи, параметры подключения).

    Взаимодействие между модулями происходит следующим образом. Пользователь открывает в браузере главную страницу (index.html). JavaScript-код на странице отправляет асинхронный POST-запрос к серверу (например, на /api/predict-yield). Серверный модуль Flask получает запрос, извлекает параметры (культура, регион, год, температура, осадки, пестициды) и вызывает метод predict\_yield модуля ml\_analytics. В свою очередь, ml\_analytics вызывает метод predict соответствующей ML-модели. Результат в формате JSON возвращается клиенту, и JavaScript динамически обновляет содержимое страницы без перезагрузки.

    Данные для ML-моделей хранятся в файле crop\_yield.csv в формате CSV.

\subsection{Реализация серверной части}

    Серверная часть реализована на языке Python с использованием микрофреймворка Flask. Основной файл приложения — app.py — содержит маршруты для обработки HTTP-запросов. Flask был выбран благодаря своей лёгкости, простоте настройки и гибкости. Он не требует сложной конфигурации и идеально подходит для небольших и средних веб-приложений.

    Ниже представлен фрагмент кода с основными маршрутами.

\begin{verbatim}
from flask import Flask, render_template, request, jsonify
from services.ml_analytics import ml_analytics
from services.ai_assistant import ai_assistant

app = Flask(__name__)

@app.route('/')
def index():
    return render_template('index.html')

@app.route('/chat')
def chat():
    return render_template('chat.html')

@app.route('/api/predict-yield', methods=['POST'])
def predict_yield():
    data = request.get_json()
    result = ml_analytics.predict_yield(
        crop=data.get('crop'),
        area=data.get('area'),
        year=int(data.get('year')),
        temperature=float(data.get('temperature')),
        rainfall=float(data.get('rainfall')),
        pesticides=float(data.get('pesticides'))
    )
    return jsonify(result)

@app.route('/api/forecast', methods=['POST'])
def forecast():
    data = request.get_json()
    result = ml_analytics.forecast_future(
        crop=data.get('crop'),
        start_year=int(data.get('start_year')),
        end_year=int(data.get('end_year')),
        temp_trend=float(data.get('temp_trend', 0.1)),
        rain_trend=float(data.get('rain_trend', 0))
    )
    return jsonify(result)

@app.route('/api/compare-crops', methods=['POST'])
def compare_crops():
    data = request.get_json()
    result = ml_analytics.compare_crops(
        temperature=float(data.get('temperature')),
        rainfall=float(data.get('rainfall')),
        pesticides=float(data.get('pesticides')),
        year=int(data.get('year'))
    )
    return jsonify(result)

@app.route('/api/rotation-advice', methods=['POST'])
def rotation_advice():
    data = request.get_json()
    result = ml_analytics.rotation_advice(data.get('last_crop'))
    return jsonify(result)

@app.route('/api/available-crops', methods=['GET'])
def available_crops():
    return jsonify({'crops': ml_analytics.get_available_crops()})

@app.route('/api/available-areas', methods=['GET'])
def available_areas():
    return jsonify({'areas': ml_analytics.get_available_areas()})

@app.route('/api/chat', methods=['POST'])
def chat_api():
    data = request.get_json()
    result = ai_assistant.chat(data.get('message'))
    return jsonify({'response': result['response']})

@app.route('/api/clear-chat', methods=['POST'])
def clear_chat():
    ai_assistant.clear_history()
    return jsonify({'success': True})

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=5000)
\end{verbatim}

    Как видно из кода, Flask-приложение определяет два типа маршрутов. Статические маршруты (\texttt{/} и \texttt{/chat}) возвращают HTML-страницы. API-маршруты (\texttt{/api/predict-yield}, \texttt{/api/compare-crops}, \texttt{/api/chat}) обрабатывают POST-запросы, извлекают данные из JSON-тела запроса, вызывают соответствующие функции и возвращают результаты также в формате JSON.

    Использование декоратора \texttt{@app.route} позволяет связать URL-адрес с функцией-обработчиком. Параметр \texttt{methods=['POST']} указывает, что маршрут принимает только POST-запросы. Функция \texttt{request.get\_json()} извлекает данные из тела запроса. Функция \texttt{jsonify()} преобразует словарь Python в JSON-ответ.

    При запуске приложение слушает все сетевые интерфейсы (\texttt{host=0.0.0.0}) на порту 5000. Параметр \texttt{debug=True} включает режим отладки, при котором приложение автоматически перезагружается при изменениях в коде.

\subsection{Реализация ML-модели прогнозирования урожайности и сравнения культур}

    Модель прогнозирования урожайности реализована в классе \texttt{YieldPredict} файла yield\_predictor.py. Для обучения используется алгоритм Random Forest Regressor из библиотеки scikit-learn. Random Forest был выбран из-за своей устойчивости к переобучению, способности работать с разнородными признаками и автоматического определения важности признаков.

    Ниже представлен фрагмент кода с основными методами.

\begin{verbatim}
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.preprocessing import StandardScaler, LabelEncoder

class YieldPredictor:
    def __init__(self, data_path="data/crop_yield.csv"):
        self.model = RandomForestRegressor(n_estimators=200)
        self.scaler = StandardScaler()
        self.crop_encoder = LabelEncoder()
        self.area_encoder = LabelEncoder()
        self._train_model(data_path)
    
    def _train_model(self, data_path):
        df = pd.read_csv(data_path)
        df['crop_enc'] = self.crop_encoder.fit_transform(df['Item'])
        df['area_enc'] = self.area_encoder.fit_transform(df['Area'])
        
        feature_cols = [
            'crop_enc', 'area_enc', 'Year', 'avg_temp',
            'average_rain_fall_mm_per_year', 'pesticides_tonnes'
        ]
        X = df[feature_cols].values
        y = df['hg/ha_yield'].values
        
        X_scaled = self.scaler.fit_transform(X)
        self.model.fit(X_scaled, y)
    
    def predict(self, crop, area, year, temperature, rainfall, pesticides):
        crop_enc = self.crop_encoder.transform([crop])[0]
        area_enc = self.area_encoder.transform([area])[0]
        features = [[
            crop_enc, area_enc, year, temperature, rainfall, pesticides
        ]]
        features_scaled = self.scaler.transform(features)
        return self.model.predict(features_scaled)[0]
\end{verbatim}

    Метод \texttt{\_train\_model} выполняет полный цикл обучения: загрузку данных из CSV-файла, кодирование категориальных признаков (культура и регион) с помощью \texttt{LabelEncoder}, масштабирование числовых признаков с помощью \texttt{StandardScaler}, обучение модели Random Forest с 200 деревьями. Модель сохраняется в атрибут \texttt{self.model}.

    Метод \texttt{predict} преобразует входные параметры пользователя в ту же форму, что и обучающие данные: кодирует культуру и регион, формирует вектор признаков, масштабирует его и передаёт в обученную модель. Результат — предсказанная урожайность в центнерах с гектара.

    Модуль сравнения культур реализован в классе \texttt{CropComparator} файла crop\_comparator.py. В отличие от регрессии (прогнозирование числового значения), здесь решается задача многоклассовой классификации: для заданных климатических условий определить, какая культура наиболее подходит.

\begin{verbatim}
from sklearn.ensemble import RandomForestClassifier

class CropComparator:
    def __init__(self, data_path="data/crop_yield.csv"):
        self.model = RandomForestClassifier(n_estimators=100)
        self.scaler = StandardScaler()
        self.crop_encoder = LabelEncoder()
        self._train_model(data_path)
    
    def compare(self, temperature, rainfall, pesticides, year):
        features = [[temperature, rainfall, pesticides, year]]
        features_scaled = self.scaler.transform(features)
        probabilities = self.model.predict_proba(features_scaled)[0]
        
        results = []
        for i, prob in enumerate(probabilities):
            crop = self.crop_encoder.inverse_transform([i])[0]
            results.append({
                'crop': crop,
                'suitability': round(prob * 100, 1)
            })
        
        results.sort(key=lambda x: x['suitability'], reverse=True)
        return {
            'ranking': results[:5],
            'best_crop': results[0]['crop']
        }
\end{verbatim}

    Ключевое отличие от регрессии — использование метода \texttt{predict\_proba}, который возвращает не один класс, а распределение вероятностей по всем возможным классам (культурам). Это позволяет построить рейтинг культур и показать пользователю не только лучшую, но и альтернативные варианты.

\subsection{Реализация ИИ-ассистента и клиентской части}

    ИИ-ассистент реализован в классе \texttt{AIAssistant} файла ai\_assistant.py. Он обеспечивает взаимодействие с большой языковой моделью через OpenRouter API \cite{openrouter} и содержит fallback-режим на случай недоступности API.

    Ниже представлен фрагмент кода класса.

\begin{verbatim}
import urllib.request
import json
import os

class AIAssistant:
    def __init__(self):
        self.api_key = os.getenv('OPENROUTER_API_KEY')
        self.model = 'gpt-oss-120b:free'
        self.api_url = "https://openrouter.ai/api/v1/chat/completions"
        self.system_prompt = "Ты опытный агроном. Отвечай на русском языке кратко."
    
    def _send_request(self, messages):
        payload = {
            "model": self.model,
            "messages": messages,
            "temperature": 0.7,
            "max_tokens": 800
        }
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        req = urllib.request.Request(
            self.api_url,
            data=json.dumps(payload).encode('utf-8'),
            headers=headers
        )
        with urllib.request.urlopen(req, timeout=30) as response:
            result = json.loads(response.read().decode('utf-8'))
            return result['choices'][0]['message']['content']
    
    def chat(self, user_message):
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": user_message}
        ]
        response = self._send_request(messages)
        if response:
            return {"success": True, "response": response}
        return self._fallback_response(user_message)
    
    def _fallback_response(self, question):
        q = question.lower()
        if 'томат' in q and 'пятна' in q:
            return {"success": False, "response": "Фитофтороз: бордоская жидкость"}
        elif 'огур' in q:
            return {"success": False, "response": "Огурцы: полив теплой 
        else:
            return {"success": False, "response": "Задайте вопрос о растениях"}
\end{verbatim}

    Системный промпт (\texttt{system\_prompt}) задаёт роль и стиль ответа. Параметр \texttt{timeout=30} ограничивает время ожидания ответа от API. Fallback-режим содержит эвристические правила для наиболее частых вопросов (томаты, огурцы), что обеспечивает базовую функциональность при отсутствии интернета или проблемах с API.

    Клиентская часть реализована в виде двух HTML-страниц: index.html (главная страница) и chat.html (страница чата). Каждая страница содержит CSS-стили для оформления и JavaScript-код для взаимодействия с сервером. JavaScript-код использует fetch API для отправки POST-запросов к серверу и динамического обновления страницы. На странице чата реализован диалоговый интерфейс: пользователь вводит вопрос в текстовое поле, JavaScript отправляет запрос к серверу, ответ от ИИ-ассистента отображается в области чата.

from sklearn.preprocessing import StandardScaler, LabelEncoder
import pickle
import os

class CropComparator:
    def __init__(self, data_path="data/crop_yield.csv", model_path="models/comparator_model.pkl"):
        self.data_path = data_path
        self.model_path = model_path
        self.model = None
        self.scaler = StandardScaler()
        self.crop_encoder = LabelEncoder()
        self.use_fallback = False
        
        if os.path.exists(model_path):
            self._load_model()
        else:
            self._train_model()
    
    def _train_model(self):
        print("Обучение ML модели для сравнения культур...")
        df = pd.read_csv(self.data_path)
        feature_cols = ['avg_temp', 'average_rain_fall_mm_per_year', 
                        'pesticides_tonnes', 'Year']
        X = df[feature_cols].values
        y = df['Item'].values
        y_encoded = self.crop_encoder.fit_transform(y)
        X_scaled = self.scaler.fit_transform(X)
        
        self.model = RandomForestClassifier(n_estimators=100, max_depth=10)
        self.model.fit(X_scaled, y_encoded)
        
        os.makedirs("models", exist_ok=True)
        with open(self.model_path, 'wb') as f:
            pickle.dump({
                'model': self.model,
                'scaler': self.scaler,
                'crop_encoder': self.crop_encoder
            }, f)
    
    def compare(self, temperature, rainfall, pesticides, year):
        features = np.array([[temperature, rainfall, pesticides, year]])
        features_scaled = self.scaler.transform(features)
        probabilities = self.model.predict_proba(features_scaled)[0]
        
        results = []
        for i, prob in enumerate(probabilities):
            crop = self.crop_encoder.inverse_transform([i])[0]
            results.append({
                'crop': crop,
                'suitability': round(prob * 100, 1)
            })
        
        results.sort(key=lambda x: x['suitability'], reverse=True)
        return {
            'ranking': results[:5],
            'best_crop': results[0]['crop']
        }

import urllib.request
import json
import os

class AIAssistant:
    def __init__(self):
        self.api_key = os.getenv('OPENROUTER_API_KEY')
        self.model = 'gpt-oss-120b:free'
        self.api_url = "https://openrouter.ai/api/v1/chat/completions"
        self.system_prompt = "Ты опытный агроном. Отвечай на русском языке кратко."
    
    def chat(self, user_message: str) -> dict:
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": user_message}
        ]
        response = self._send_request(messages)
        if response:
            return {"success": True, "response": response}
        return self._fallback_response(user_message)
    
    def _send_request(self, messages):
        payload = {
            "model": self.model,
            "messages": messages,
            "temperature": 0.7,
            "max_tokens": 800
        }
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        req = urllib.request.Request(
            self.api_url,
            data=json.dumps(payload).encode('utf-8'),
            headers=headers
        )
        with urllib.request.urlopen(req, timeout=30) as response:
            result = json.loads(response.read().decode('utf-8'))
            return result['choices'][0]['message']['content']
    
    def _fallback_response(self, question: str):
        q = question.lower()
        if 'томат' in q and 'пятна' in q:
            return {"success": False, "response": "Фитофтороз: бордоская жидкость"}
        elif 'огур' in q:
            return {"success": False, "response": "Огурцы: полив теплой водой ежедневно"}
        else:
            return {"success": False, "response": "Задайте вопрос о растениях"}

import pandas as pd
import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.preprocessing import StandardScaler, LabelEncoder
from models.crop_comparator import comparator
from models.rotation_predictor import rotation_predictor

class MLAnalytics:
    def __init__(self, data_path="data/crop_yield.csv"):
        self.data_path = data_path
        self.yield_model = None
        self.scaler = StandardScaler()
        self.crop_encoder = LabelEncoder()
        self.area_encoder = LabelEncoder()
        self.comparator = comparator
        self.rotation = rotation_predictor
        self._train_yield_model()
    
    def _train_yield_model(self):
        df = pd.read_csv(self.data_path)
        df['crop_enc'] = self.crop_encoder.fit_transform(df['Item'])
        df['area_enc'] = self.area_encoder.fit_transform(df['Area'])
        
        feature_cols = ['crop_enc', 'area_enc', 'Year', 'avg_temp', 
                        'average_rain_fall_mm_per_year', 'pesticides_tonnes']
        X = df[feature_cols].values
        y = df['hg/ha_yield'].values
        X_scaled = self.scaler.fit_transform(X)
        
        self.yield_model = RandomForestRegressor(n_estimators=200, random_state=42)
        self.yield_model.fit(X_scaled, y)
    
    def predict_yield(self, crop, area, year, temperature, rainfall, pesticides):
        crop_enc = self.crop_encoder.transform([crop])[0]
        area_enc = self.area_encoder.transform([area])[0]
        features = np.array([[crop_enc, area_enc, year, temperature, rainfall, pesticides]])
        features_scaled = self.scaler.transform(features)
        prediction = self.yield_model.predict(features_scaled)[0]
        
        return {
            'predicted_yield': round(prediction, 1),
            'unit': 'tsd/ha',
            'confidence': 70
        }
    
    def compare_crops(self, temperature, rainfall, pesticides, year):
        return self.comparator.compare(temperature, rainfall, pesticides, year)
    
    def rotation_advice(self, last_crop):
        return self.rotation.get_recommendations(last_crop)

ml_analytics = MLAnalytics()

import os
from pathlib import Path

def load_env(env_file=".env"):
    path = Path(env_file)
    if not path.exists():
        return
    with open(path, 'r', encoding='utf-8') as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith('#'):
                continue
            if '=' in line:
                key, value = line.split('=', 1)
                os.environ[key.strip()] = value.strip().strip('"').strip("'")

def get_env(key, default=None):
    return os.environ.get(key, default)
